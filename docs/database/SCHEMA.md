# Database Schema

PostgreSQL 17. Models: `backend/src/unjobless/db/models/`. Migrations: `backend/alembic/versions/` (Alembic). Diagram: [`docs/domain/ERD.mmd`](../domain/ERD.mmd).

## Creating and migrating

```bash
make dev-db           # local Postgres on 127.0.0.1:5433 (dev only)
make migrate          # = cd backend && uv run unjobless migrate  (alembic upgrade head)
cd backend && uv run alembic check          # fails if models and migrations drift
cd backend && uv run alembic revision --autogenerate -m "describe change"   # new migration
```

The production `migrate` Compose service runs `unjobless migrate` before `api`/`worker` start. No manual DB steps exist; extensions (`pg_trgm`, `unaccent`) are created by the first migration.

## Conventions

- Primary keys: `BIGINT GENERATED BY DEFAULT AS IDENTITY`.
- Timestamps: `timestamptz` (UTC). Calendar dates whose timezone is unknown use `date` + a `*_tz_uncertain` flag.
- Enums: `VARCHAR(40)` + an explicit `CHECK (<col> IN (...))` constraint named `ck_<table>_<col>_enum`. Adding a value = a migration that replaces the constraint (no `ALTER TYPE` lock issues).
- Constraint names follow a fixed naming convention (`pk_`, `fk_`, `uq_`, `ck_`, `ix_`) so migrations are deterministic.
- JSONB only for flexible payloads (see domain model §4). Every filter/sort column is typed and indexed.

## Integrity rules enforced by the database

| Rule | Mechanism |
|---|---|
| Exactly one owner | `owner_account.singleton = 1` + unique |
| One master profile / preferences row | `singleton` pattern |
| Enabled source must have an approved/restricted policy review | `ck_sources_enabled_requires_policy` |
| Minimum schedule interval 5 min; bounded concurrency and rate | `ck_sources_*` |
| No overlapping runs per source | partial unique index `uq_source_runs_one_active` |
| Raw versions are unique per content hash | `uq_raw_version_doc_hash` |
| Raw document identity per source (native id, else canonical URL) | partial unique indexes |
| Comparison has at most two distinct vacancies | `CHECK position IN (1,2)` + unique `(comparison, position)` + unique `(comparison, vacancy)` |
| Salary range ordered, non-negative; confidence in [0,1]; GPA ≤ 4 | `CHECK` constraints |
| Saved item targets exactly one of vacancy/signal | `ck_saved_opportunities_one_target` |
| One default AI provider | partial unique index `uq_ai_default` |
| Dedup pairs stored once, ordered | `CHECK vacancy_a_id < vacancy_b_id` + unique pair |

## Search

- `job_vacancies.search_vector`: generated `tsvector` (`simple` config; weights A=title/company, B=location/family/industry/skills, C=description) with a GIN index.
- `opportunity_signals.search_vector`: generated over role/company/summary.
- Trigram GIN indexes on `companies.normalized_name` and `job_vacancies.normalized_title` for fuzzy matching and dedup candidate generation.
- `pgvector` intentionally not installed (ADR 0002).

## Deletion and retention

| Data | Behaviour |
|---|---|
| Raw documents | `ON DELETE RESTRICT` from vacancy source links: raw evidence cannot be deleted while a vacancy cites it. `retention_until` drives the retention job (Block 35). |
| Raw versions | Cascade from their document. |
| Vacancy children (skills, requirements, evidence, history, matches) | Cascade from the vacancy. |
| Profile versions | Tailored resumes `RESTRICT` deletion of the profile version they were generated from. |
| Sessions, login attempts, fetch logs | Pruned by a periodic job. |
| Audit events | Retained. Never contain secrets or CV text. |

## Tests

`backend/tests/test_schema.py` migrates the test database from empty and checks the constraints above (owner singleton, policy guard, enum checks, no overlapping runs, raw version uniqueness, comparison max-two, salary order, full-text search).
